# qingshu101 注册目录

这是仅供运营者使用的隐藏管理入口，不是客户登录入口。

## 上线配置

1. 将 `qingshu101.example.com` 的 DNS 指向服务器，并将服务端 `QINGSHU101_HOST` 设置为实际主机名（本地开发默认允许 `localhost`）。
2. 在服务器环境变量设置一个随机、至少 16 个字符的 `QINGSHU101_ADMIN_KEY`，不要写入前端或提交到仓库。
3. 用 HTTPS 反向代理到应用端口（默认 `3018`）。访问 `https://qingshu101.example.com/`，或本地开发访问 `/qingshu101`。
4. 首次进入输入管理密钥。服务端签发 8 小时 HttpOnly 管理 Cookie，退出或过期后需重新输入；生产环境必须使用 HTTPS。

## 数据边界

管理目录按分页展示姓名、电话、创建时间和更新时间；密码明文、盐值、密码哈希和会话令牌永远不会返回。注册目录由服务端每 30 秒预处理刷新，进入页面不需要为每一行再次调用接口。页面每 30 秒检查一次缓存健康状态；如果刷新失败，会保留最后一次成功快照并显示“目录陈旧”，不会把失败伪装成空目录。

普通用户仍通过网站首页填写姓名、电话、密码进入。所有个人文件、策略、配置、报告和回测结果落在 `data/users/<user_id>/`，市场行情等公共只读数据保留在共享数据根目录。

## 服务器后台刷新

实时行情的 provider、轮询间隔和财务后台周期保存在 `data/server_config.json`，不属于任何用户。实时行情开启后由服务端 QuoteService 统一轮询，账户自选只按账户工作区并集批量请求 TeaJoin；页面请求不会代替后台采集。若需要启用财务自动预处理，可在服务器配置中设置：

```json
{"financial_schedule": {"enabled": true, "interval_days": 7}}
```

状态接口会区分 `success`、`empty`、`stale`、`provider_unavailable` 和 `error`，失败时保留最后一次有效快照，不会用零值或空目录冒充最新数据。每个 HTTP 响应带有 `X-Request-ID`，可用来关联服务器日志。
