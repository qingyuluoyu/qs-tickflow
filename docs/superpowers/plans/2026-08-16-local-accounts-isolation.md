# 本地账户入口与用户数据隔离

## 目标

在不新增独立登录页面的前提下，让用户进入站点时填写姓名、电话、密码；账户首次使用自动创建、已有电话按密码进入；右上角显示姓名并可退出。公共行情数据继续共享，个人数据必须按用户目录隔离。

## 边界与不变量

- 账户与会话使用本地 SQLite，密码只保存 PBKDF2 哈希，Cookie 保存随机会话令牌。
- 姓名、电话、密码不做业务格式和最小长度限制；仅设置请求体字节上限，防止超大输入造成资源耗尽，不截断输入。
- 市场行情、财务、指数等只读数据保持共享。
- 自选、偏好、扩展数据、策略/监控配置、报告、告警和回测产物使用 `data/users/<user_id>/`。
- 旧单用户认证接口保留兼容代码，但账户模式启用后不再作为跨账户数据访问凭证。

## 工作包

1. 审计现有认证、数据目录、策略/报告/自选调用链与测试。
2. 先添加账户 SQLite 版本化迁移、账户服务、请求用户上下文和隔离失败测试。
3. 接入认证中间件，把有效会话绑定到用户，并把用户目录用于个人存储；保留共享行情仓库。
4. 前端增加内嵌入口卡、认证上下文、右上角姓名/退出，阻止未认证页面挂载。
5. 运行后端定向/链路测试、前端构建、浏览器双账户隔离测试，记录迁移与回滚影响。

## 迁移与回滚

账户数据库首次启动自动执行版本 1 迁移。既有 `data/user_data` 不删除；首个账户进入时复制可迁移的个人文件到其用户目录，原目录保留作为回滚副本。代码回滚时数据库表向前兼容，旧单用户认证文件仍保留。
