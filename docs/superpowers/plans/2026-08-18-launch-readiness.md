# 上线前数据与 AI 链路修复计划

## 目标

在不破坏现有用户隔离和看板数据链路的前提下，完成上线前的六项修复：平台默认 DeepSeek 配置、用户自定义 AI 隔离、A 股公告完整性、清数一号策略可命中、仓位回测稳定、个股分析七模块横向切换及资金流日期解析。

## 约束与边界

- 不把 API Key 写入受版本控制的源码、前端 bundle、测试输出或日志；平台密钥只通过忽略的本地 secret/env 注入。
- 复用现有 OpenAI-compatible AI provider、新闻 provider、回测引擎和账号隔离存储，不引入新基础设施。
- 公告分页和预加载均有硬上限、超时与失败分类，避免请求风暴；用户私有数据继续按 current_user/account_id 查询。
- 所有金融日期使用数据源字段和 Asia/Shanghai 交易日语义，不用浏览器自然日覆盖源日期。

## 工作包 1：平台 AI 默认与覆盖隔离

1. 先为默认配置、共享 secret 读取和单用户 override 补充回归测试。
2. 将 tracked 配置默认值改为 `https://api.deepseek.com`（适配层自动补 `/v1`）和 `deepseek-v4-flash`；本地 ignored secret 使用用户提供的 DeepSeek 平台配置但不输出密钥。
3. 保留用户自己的 provider/base URL/model/key 保存、删除、解析和 Fernet 隔离；补充两个账号的解析测试。
4. 检查设置接口只返回掩码和 source，不返回密钥。

## 工作包 2：A 股公告数据完整性

1. 先补 `stock_insight.announcements` 多页、去重、上限和单页失败测试。
2. 将 Eastmoney 公告读取改为有限分页（最多 3 页、每页最多 50 条，按公告日期倒序去重），保留 provider 错误语义。
3. 将公告/资讯预加载窗口从 7 天提升到有界的 30 天，并保持每用户 watchlist 隔离和 provider 缓存。
4. 增加 API/provider 集成测试，验证搜索、股票过滤和数据源失败不会伪造空数据。

## 工作包 3：清数一号与仓位回测

1. 定位清数一号的两个极端指标及其 schema/计算调用方，先补策略命中和参数边界测试。
2. 移除这两个极端过滤条件，保留可解释的基础过滤和排序，确保没有候选时返回明确结果而非异常。
3. 复现并修复 `position` 模式下空候选、资金不足、持仓上限和交易日数据缺失导致的回测失败；保持 T+1、费用、滑点和仓位上限口径。
4. 增加成功路径、空候选路径、非法仓位参数和重复运行测试。

## 工作包 4：个股分析七模块与资金流

1. 补资金流 API 日期/空响应解析测试，明确 `无可用数据日期` 只在源确实没有日期时显示。
2. 修正资金流字段和日期标准化，允许最近交易日数据；源失败与无数据分开返回。
3. 将估值、财务、研报、公告、新闻、资金面、龙虎榜改为横向 tab，默认只请求当前 tab，点击切换后展示对应内容，保持代码/股票查询和权限不变。
4. 补组件和 API 类型回归，确保其他页面不受影响。

## 工作包 5：上线前联调与回归

1. 运行受影响后端测试，再运行完整后端测试、ruff、前端 lint/build。
2. 启动前后端进行健康检查和关键页面冒烟：登录/账号切换、公告弹窗、清数一号筛选、仓位回测、个股分析 tab、资金流。
3. 检查 diff、secret 泄露、迁移兼容和日志脱敏；记录仍需上线环境注入的配置。

## 回滚

- 配置修改可回滚到上一版本；用户 override 数据结构不变，无数据库迁移。
- 公告分页和前端 tab 均为兼容性增强，若 provider 限流可通过配置降低页数/窗口并回退代码。
- 策略参数变更不删除历史策略记录；如需恢复，使用策略管理中的初始版本恢复。
