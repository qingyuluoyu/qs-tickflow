# A 股当日数据截止规则实施计划

## 目标

统一看板、指数和个股 K 线的“截至日期/时间”口径：所有当前日数据必须受北京时间、A 股交易日历和交易时段约束；盘中只使用数据源已经返回的分钟/实时数据，日线指标不使用未收盘的半日蜡烛；休市或数据源没有当前日数据时，明确回退到最近已完成交易日，不伪造当前日数据。请求路径保持轻量，网络刷新由后台预加载和有界缓存完成。

## 边界与设计

- 北京时间固定为业务时区，交易时段为 09:30–11:30、13:00–15:00。
- 交易日前、午休和收盘后分别有明确 session 状态；周末/节假日使用交易日历判断，不使用工作日推断。
- 当前日分钟 K 线按数据源最后一根已返回的时间截断；没有当前日分钟数据时返回最近完整日线并标注状态，不生成空的或虚假的分钟柱。
- 当前日实时价与完整日线分离：盘中技术指标和日线统计只基于最近完成日线，收盘后才允许当前日进入完整日线口径。
- 缓存键至少包含标的、资产类型、周期、交易日、数据源和截止 session；后台刷新采用固定周期与有界超时，前端读快照不等待全市场网络请求。

## 工作包

1. 扩展 `backend/app/market_time.py`，提供交易 session、交易日解析和 `as_of` 选择结果；增加盘前、午休、盘后、周末/节假日和数据缺失测试。
2. 将看板快照、指数数据和排名指标接入统一结果，携带 `trade_date`、`cutoff_time`、`session`、`is_partial`、`status`、`observed_at` 元数据。
3. 将股票/ETF/指数日线与分钟 K 线默认日期、当前日补拉和本地缓存读取接入同一解析器，保留显式历史日期行为不变。
4. 保持数据获取在后台预加载，按 30 秒刷新实时快照、按源能力设置分钟缓存，限制请求超时与重复补拉；不在 HTTP 请求中执行全市场同步。
5. 运行定向规则、provider、K 线、看板和 API 测试，完成前端构建与真实 TeaJoin 验证；记录数据源仍未发布当前日数据时的明确降级状态。

## 发布与回滚

仅增加兼容字段和默认规则，不修改历史存储结构；若新解析器发现异常，显式回退到原有最近完整日线读取。回滚代码即可恢复旧路径，已增加的元数据字段保持向后兼容。
